# Security policy and trust boundaries

Codex Pocket is unofficial, experimental source software with a privileged local Windows account broker. Use only your own accounts, PC, conversations and tailnet devices. Do not expose the bridge to the public Internet, LAN wildcards, reverse proxies, Tailscale Serve/Funnel, dynamic DNS or shared untrusted tailnets. No security inbox or response SLA is claimed. Contact a maintainer using a private channel they explicitly offer before disclosing a sensitive report; public issues must contain only synthetic reproductions. Never upload logs/config/auth/signing files, real chats or device codes.

## Boundaries

- One concrete Tailscale IPv4/port and exact configured peers; strict Host/Origin/CSRF, session, rate, CSP and body bounds. The shipped TEST_NETWORK is only a synthetic `createBridge` test fixture. Production `server/main.mjs` requires validated private configuration and Windows ACL verification before runtime state/listen. Spoofable UA/native markers are layout/capability hints, not authorization.
- HTTP is inside Tailscale's encrypted tailnet; the browser cookie is not a substitute for tailnet access controls. A compromised permitted phone/session can perform the explicit operations available to that user. Paired-device physical access, browser origin storage and lock-screen redaction matter. Do not store sensitive snippets unnecessarily.
- Desktop-owned threads are read/sent through exactly seven allowlisted tools. Standalone child permits only initialize/account reads/thread reads; never writer/resume/fork/config. No arbitrary RPC, shell, environment or file proxy. Reasoning bodies and unrelated tool output are excluded before interpretation.
- Every mutation requires an explicit human action, fresh ownership/source/model checks and an idempotent journal. Ambiguous delivery never automatically replays; acknowledging uncertainty does not prove delivery. Questions are hidden only for exact native answered or exact source delivery evidence; delivered is not native form completion/approval.
- Windows local state is outside source and virtualized AppData, CurrentUser DPAPI-encrypted account records and CurrentUser-only owner/DACL/canonical non-link/single-link identity checks. Same-user malware and a compromised Codex desktop are outside the protection boundary; DPAPI is not protection from that user. The broker can gracefully close/restart exact owned Codex processes and publish a supported shared file login after explicit confirmation. It cannot provide a global atomic CAS against every writer or promise power-loss durability. Recovery retains encrypted material and refuses competing writes. Phone pairing is independent of Codex account revisions.
- Human login is through the fixed official device-code flow in an isolated child home. No token in web/storage/URL/logs; no browser OAuth/provider fallback/global auth-policy rewrite. Unsupported storage/managed/keyring/custom modes remain blocked. Saving a shared login does not independently prove Desktop's internal account view.
- Configured private directories are excluded from media/result references regardless of directory name; only exact verified session-owned upload images bypass that exclusion. First-use private stores must be new/empty and receive an ownership marker; existing nonempty unrelated stores are not imported. Signing uses a per-store mutex and bounded canonical CurrentUser-only single-link read leases without write/delete sharing. This still does not defend against same-user malicious processes.
- Native Android exact build-time origin/port/domain allowlist, no generic JS interface, no file/content access, no redirect following for native requests, bounded bodies, readonly system picker and explicit SAF/share. Opt-in nonsticky foreground notifications may be delayed by the OS. No boot receiver/broad storage/package-install permission. APK signing is per installer, never a repository key.

## Safe testing and reporting

Use Node synthetic fixtures by default. Review Windows synthetic helper scripts before opt-in; never redirect them at real profiles. Real send/switch/install/service/task actions require deliberate operator approval and verification. Do not claim synthetic DOM/source contracts prove CSS geometry, physical-device behavior or live delivery.

Run the source-manifest scanner and manually review every source file before publishing. It cannot prove the absence of all secrets, personal information or licensing problems. Do not publish private directories/builds/keys even if a scanner misses them. No automatic update/download/install path is provided; review source changes and preserve your private signing identity for updates.
